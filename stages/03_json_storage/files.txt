ETAPA 03 — ALMACENAMIENTO TEMPORAL EN JSON
==========================================

PROPÓSITO
---------
Definir el mecanismo inicial para guardar y cargar una lista de actividades en
un archivo local con formato JSON.

ARCHIVOS DE LA ETAPA
--------------------
- storage.py
- demo.py
- preview.html

ADAPTACIÓN AL TAMAÑO DE LA VENTANA
----------------------------------
La demostración visual de guardado y carga debe adaptarse al ancho disponible.
Los mensajes, ejemplos JSON y botones deben usar contenedores flexibles,
permitir saltos de línea y pasar a una columna si el espacio se reduce.

======================================================================
ARCHIVO: storage.py
======================================================================

RESULTADO ESPERADO
------------------
Crear dos funciones pequeñas: guardar datos en JSON y cargar datos desde JSON.
Este archivo no debe saber nada de ventanas ni de la agenda visual.

LIBRERÍAS QUE SE PUEDEN USAR
-----------------------------
- json para convertir entre texto y datos de Python.
- pathlib.Path para trabajar con rutas.
- No usar Tkinter ni SQLite.

LECCIÓN 1 — RUTAS CON PATH
--------------------------
Path representa una ruta sin depender de concatenar textos manualmente.

Fragmento:
    from pathlib import Path
    ruta = Path("data") / "agenda.json"

LECCIÓN 2 — CONVERTIR DATOS A JSON
----------------------------------
json.dumps convierte una lista o diccionario en texto JSON.

Fragmento:
    import json
    texto = json.dumps(datos, indent=2, ensure_ascii=False)

indent=2 hace el archivo legible y ensure_ascii=False conserva tildes.

LECCIÓN 3 — GUARDAR TEXTO EN UTF-8
----------------------------------
Path.write_text escribe texto y permite indicar la codificación.

Fragmento:
    ruta.parent.mkdir(parents=True, exist_ok=True)
    ruta.write_text(texto, encoding="utf-8")

Crear la carpeta superior evita errores cuando data todavía no existe.

LECCIÓN 4 — DISEÑAR guardar
---------------------------
La función recibe list[dict] y Path, convierte los datos en texto y los guarda.

Firma esperada:
    def guardar(datos: list[dict], ruta: Path) -> None:
        ...

LECCIÓN 5 — LEER Y CONVERTIR JSON
---------------------------------
Path.read_text lee el texto. json.loads convierte el texto en objetos Python.

Fragmento:
    texto = ruta.read_text(encoding="utf-8")
    datos = json.loads(texto)

LECCIÓN 6 — ARCHIVO INEXISTENTE
-------------------------------
Si la ruta todavía no existe, cargar debe devolver una lista vacía. Así la
aplicación puede empezar sin datos.

Fragmento:
    if not ruta.exists():
        return []

Si el contenido no es una lista, se puede lanzar ValueError con un mensaje
claro.

======================================================================
ARCHIVO: demo.py
======================================================================

PROPÓSITO
---------
Demostrar storage.py sin tocar archivos permanentes del proyecto. El demo es un programa corto
que guarda, carga e imprime una lista.

LIBRERÍAS QUE SE PUEDEN USAR
-----------------------------
- tempfile.TemporaryDirectory para crear una carpeta de prueba.
- pathlib.Path para construir la ruta.
- Las funciones guardar y cargar de storage.py.

LECCIÓN 1 — CARPETA TEMPORAL
----------------------------
TemporaryDirectory elimina la carpeta al salir del bloque with.

Fragmento:
    from tempfile import TemporaryDirectory

    with TemporaryDirectory() as carpeta:
        ruta = Path(carpeta) / "agenda.json"

LECCIÓN 2 — DATOS DE EJEMPLO
----------------------------
Crear una lista con un diccionario que tenga titulo, fecha, hora y descripcion.

Fragmento:
    datos = [{
        "titulo": "Clase",
        "fecha": "2026-10-23",
        "hora": "18:00",
        "descripcion": "Practicar JSON",
    }]

LECCIÓN 3 — FLUJO DEL DEMO
--------------------------
1. Crear la ruta temporal.
2. Preparar la lista.
3. Llamar guardar.
4. Llamar cargar.
5. Imprimir la lista cargada.

RESTRICCIONES
-------------
- No modificar archivos permanentes del proyecto.
- No abrir ventanas.
- No usar SQLite.
- No dejar carpetas temporales.

PRUEBA FUNCIONAL OPCIONAL EN EL PC
-------------------
Ejecutar:

    python stages/03_json_storage/demo.py

Debe imprimirse la misma información guardada. Si se borra el archivo temporal,
el programa debe poder volver a ejecutarse sin preparación adicional.

INTEGRACIÓN DESPUÉS DE APROBAR EL STAGE
---------------------------------------
Las funciones terminadas permanecen aisladas en esta carpeta. Después de
validar la etapa, se conectan en `src/`, se coordinan desde `main.py` y se
registran en `config/integration.json` si su salida visual queda activa.

CONTRATO DE INDEPENDENCIA E INTEGRACIÓN
----------------------------------------
Este stage se construye como un módulo independiente. No debe importar archivos
de otros stages ni depender de que otra etapa esté terminada. Sus datos de
prueba, entradas, salidas y validaciones pertenecen únicamente a este módulo.

preview.html representa este stage y se revisa desde la única página principal:
https://awooolab.github.io/Agenda_SENA/

Solo muestra los módulos aprobados que estén registrados en
config/integration.json.

Después de aprobar el stage, la integración se realiza fuera de esta carpeta,
en src/, main.py y config/integration.json. El estudiante no modifica esos
archivos durante la lección. La acumulación ocurre únicamente en la aplicación
integrada.

Antes de integrar, comprobar la entrada independiente, la salida producida,
las funciones públicas, los datos de prueba, las validaciones, los errores y
el punto de conexión futuro. Este módulo no debe conservar funciones de otros
stages dentro de su propio código.
