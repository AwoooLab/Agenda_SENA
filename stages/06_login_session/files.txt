============================================

PROPÓSITO
---------

======================================================================
ARCHIVO: password.py
======================================================================

PROPÓSITO
---------
Convertir una contraseña en un resumen seguro y comprobarla después sin guardar
la contraseña original.

LIBRERÍAS PERMITIDAS
--------------------
- secrets para crear una sal aleatoria.
- hashlib para PBKDF2.
- hmac para comparar de forma segura.
- No usar librerías externas.

LECCIÓN 1 — POR QUÉ NO SE GUARDA LA CONTRASEÑA
----------------------------------------------
La contraseña original es un secreto. La base solo debe guardar un resumen
irreversible y una sal diferente para cada usuario.

LECCIÓN 2 — CREAR UNA SAL
-------------------------
Una sal es un valor aleatorio que evita que dos contraseñas iguales produzcan
el mismo resumen.

Fragmento:
    import secrets
    salt = secrets.token_hex(16)

LECCIÓN 3 — DERIVAR EL RESUMEN
------------------------------
PBKDF2 aplica muchas iteraciones para dificultar ataques de fuerza bruta.

Fragmento orientativo:
    import hashlib
    resumen = hashlib.pbkdf2_hmac(
        "sha256",
        password.encode("utf-8"),
        salt.encode("utf-8"),
        100000,
    )

Convertir el resultado a hexadecimal con .hex().

LECCIÓN 4 — VERIFICAR
---------------------
Crear nuevamente el resumen usando la sal guardada y comparar con
hmac.compare_digest.

Fragmento:
    import hmac
    hmac.compare_digest(resumen_nuevo, resumen_guardado)

FUNCIONES OBLIGATORIAS
----------------------
    crear_credenciales(password) -> tuple[str, str]
    verificar_password(password, salt, password_hash) -> bool

REGLAS
------
- Rechazar contraseñas de menos de ocho caracteres en el servicio.
- No imprimir contraseñas.
- No incluir contraseñas de ejemplo en el código.
- No devolver la contraseña original.

======================================================================
ARCHIVO: auth_service.py
======================================================================

PROPÓSITO
---------
Conectar el repositorio de usuarios con las funciones de contraseñas y guardar
en memoria quién inició sesión.

LIBRERÍAS
---------
- password.py de esta etapa.
- user.py y user_repository.py de la etapa anterior.
- No usar Tkinter dentro del servicio.

LECCIÓN 1 — DEPENDENCIAS
------------------------
El servicio recibe el repositorio en el constructor para no crear conexiones
por dentro.

Fragmento:
    class ServicioAutenticacion:
        def __init__(self, repositorio):
            self.repositorio = repositorio
            self._usuario_actual = None

LECCIÓN 2 — ESTABLECER CONTRASEÑA
---------------------------------
crear_credenciales devuelve hash y salt. Luego actualizar_credenciales los
guarda en el usuario indicado.

LECCIÓN 3 — INICIAR SESIÓN
--------------------------
1. Buscar por username.
2. Si no existe, devolver None.
3. Si está inactivo, devolver None.
4. Verificar la contraseña.
5. Si es correcta, guardar el usuario en _usuario_actual.
6. Devolver el usuario.

LECCIÓN 4 — CERRAR SESIÓN
-------------------------
Cerrar sesión significa asignar None al usuario actual.

MÉTODOS OBLIGATORIOS
--------------------
    establecer_password(user_id, password)
    iniciar_sesion(username, password)
    cerrar_sesion()
    usuario_actual()

ARCHIVO: login_window.py
======================================================================

PROPÓSITO
---------
Crear la pantalla visual que solicita usuario y contraseña.

LIBRERÍAS
---------
- tkinter.
- messagebox solo si se desea mostrar un aviso sencillo.
- auth_service.py.

LECCIÓN 1 — CAMPOS DE TEXTO
---------------------------
Entry permite escribir datos. Para ocultar una contraseña usar show="*".

Fragmento:
    entrada_password = tk.Entry(ventana, show="*")

LECCIÓN 2 — FUNCIÓN DEL BOTÓN
-----------------------------
El botón debe leer los campos, llamar a iniciar_sesion y revisar el resultado.

Fragmento:
    usuario = entrada_usuario.get().strip()
    password = entrada_password.get()

LECCIÓN 3 — FUNCIÓN DE RESPUESTA
--------------------------------
La ventana recibe on_login(usuario). Si el servicio devuelve un usuario, llama
a esa función. La ventana no debe construir la ventana principal.

DISEÑO OBLIGATORIO
------------------
- Título: Agenda SENA — Inicio de sesión.
- Tamaño: 420x300.
- Etiqueta Usuario.
- Campo Usuario.
- Etiqueta Contraseña.
- Campo Contraseña oculto.
- Botón Iniciar sesión.
- Botón Cerrar.
- Mensaje de error en español.

======================================================================
ARCHIVO: preview.html
======================================================================

PROPÓSITO
---------
Mostrar en GitHub Pages la pantalla de inicio de sesión que corresponde a
login_window.py.

CONCEPTOS NECESARIOS
--------------------
- HTML organiza los campos Usuario y Contraseña.
- type="password" oculta el texto escrito en el navegador.
- CSS organiza el formulario y muestra estados de error.
- Esta vista no autentica usuarios ni guarda contraseñas.

FRAGMENTO DE REFERENCIA
-----------------------
    <label for="password">Contraseña</label>
    <input id="password" type="password" />
    <button>Iniciar sesión</button>

Para mostrar un error visual se puede usar:

    <p class="estado-error">El usuario o la contraseña no son correctos.</p>

Subir los archivos de esta etapa y abrir únicamente la página
principal https://awooolab.github.io/Agenda_SENA/. Confirmar allí que el

CONTRATO DE INDEPENDENCIA E INTEGRACIÓN
----------------------------------------
Este stage se construye como un módulo independiente. No debe importar archivos
de otros stages ni depender de que otra etapa esté terminada. Sus datos de
prueba, entradas, salidas y validaciones pertenecen únicamente a este módulo.

preview.html representa este stage y se revisa desde la única página principal:
https://awooolab.github.io/Agenda_SENA/
La página principal no carga automáticamente todos los previews existentes.
Solo muestra los módulos aprobados que estén registrados en
config/integration.json.

Después de aprobar el stage, la integración se realiza fuera de esta carpeta,
en src/, main.py y config/integration.json. El estudiante no modifica esos
archivos durante la lección. La acumulación ocurre únicamente en la aplicación
integrada.

Antes de integrar, comprobar la entrada independiente, la salida producida,
las funciones públicas, los datos de prueba, las validaciones, los errores y
el punto de conexión futuro. Este módulo no debe conservar funciones de otros
stages dentro de su propio código.
