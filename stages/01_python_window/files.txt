ETAPA 01 — VENTANA INICIAL DE LA AGENDA
========================================

PROPÓSITO
---------
Construir la ventana inicial de Agenda SENA, que será el punto de entrada visual
de la aplicación de escritorio local. Esta etapa define la identidad de la
aplicación, las dimensiones de la ventana y el primer control interactivo para
cerrarla.

PLATAFORMA OBJETIVO
-------------------
La aplicación que se está construyendo es para un PC con Windows y se ejecuta
con Python y Tkinter. El tamaño 520x320 corresponde a la ventana de escritorio.
`preview.html` es únicamente una representación visual para revisar el diseño
en el navegador; no reemplaza ni ejecuta `app.py`.

ARCHIVO DE LA ETAPA
-------------------
- app.py
- preview.html

REGLAS GENERALES
----------------
- Trabajar desde la carpeta raíz del proyecto.
- Usar Python 3.
- Usar únicamente la biblioteca incorporada tkinter.
- No instalar paquetes externos.
- No copiar todavía código desde src/.
- No crear archivos adicionales.

======================================================================
ARCHIVO: app.py
======================================================================

PROPÓSITO DEL ARCHIVO
---------------------
Este archivo será un programa independiente. Su trabajo es crear una ventana
pequeña, mostrar información básica de la agenda y permitir cerrarla.

LIBRERÍAS QUE SE PUEDEN USAR
-----------------------------
- tkinter, incluida en Python.
- No usar SQLite, JSON, pathlib, internet ni librerías externas.

LECCIÓN 1 — IMPORTAR TKINTER
----------------------------
Tkinter contiene las herramientas para crear ventanas y controles de escritorio.
La forma corta permite escribir tk.Label y tk.Button:

Fragmento:
    import tkinter as tk

LECCIÓN 2 — CREAR LA VENTANA PRINCIPAL
--------------------------------------
tk.Tk() crea la ventana principal. Todo control de esta etapa debe pertenecer a
esa ventana.

Fragmento:
    ventana = tk.Tk()

LECCIÓN 3 — CONFIGURAR LA VENTANA
---------------------------------
Configurar el título, el tamaño y si se permite cambiar el tamaño.

Fragmentos:
    ventana.title("Agenda SENA — Etapa 01")
    ventana.geometry("520x320")
    ventana.resizable(False, False)

El texto del título debe ser exactamente el indicado. geometry recibe ancho por
alto en píxeles.

LECCIÓN 4 — MOSTRAR TEXTO CON LABEL
-----------------------------------
Un Label muestra un texto. font recibe el nombre de letra, tamaño y estilo.
pack organiza el control en la ventana.

Fragmentos:
    titulo = tk.Label(ventana, text="Agenda SENA")
    titulo.pack(pady=40)

    subtitulo = tk.Label(ventana, text="Mi agenda local para PC")
    subtitulo.pack(pady=10)

Se puede usar font=("Arial", 22, "bold") para el título.

LECCIÓN 5 — CREAR UN BOTÓN
--------------------------
Un Button muestra una acción. command recibe una función, no el resultado de
ejecutarla.

Fragmento:
    boton = tk.Button(ventana, text="Cerrar", command=ventana.destroy)
    boton.pack(pady=20)

Correcto: command=ventana.destroy
Incorrecto: command=ventana.destroy()

LECCIÓN 6 — INICIAR EL BUCLE DE LA INTERFAZ
-------------------------------------------
mainloop mantiene abierta la ventana y espera clics del usuario.

Fragmento:
    ventana.mainloop()

Sin mainloop la ventana aparece y se cierra inmediatamente.

LECCIÓN 7 — ORGANIZAR EL PUNTO DE ENTRADA
-----------------------------------------
Es recomendable colocar la construcción de la ventana dentro de main y ejecutar
main solo cuando el archivo se abra directamente.

Fragmento:
    def main():
        ...

    if __name__ == "__main__":
        main()

LÓGICA COMPLETA QUE DEBE ESCRIBIR EL ESTUDIANTE
------------------------------------------------
1. Importar tkinter como tk.
2. Definir main.
3. Crear la ventana.
4. Configurar título, tamaño y redimensionamiento.
5. Crear el título.
6. Crear el subtítulo.
7. Crear el botón Cerrar.
8. Iniciar mainloop.
9. Agregar el bloque de ejecución directa.

DISEÑO OBLIGATORIO
------------------
- Título de ventana: Agenda SENA — Etapa 01.
- Tamaño: 520x320.
- Fondo blanco o gris muy claro.
- Texto grande: Agenda SENA.
- Subtítulo: Mi agenda local para PC.
- Botón: Cerrar.
- El título y el subtítulo deben quedar centrados.

LO QUE TODAVÍA NO SE DEBE CONSTRUIR
-----------------------------------
- Formularios de citas.
- Menús.
- Usuarios.
- Inicio de sesión.
- Calendario.
- JSON o SQLite.
- Conexión a internet.

PRUEBA FUNCIONAL OPCIONAL EN EL PC
-------------------
Si se dispone de Python instalado, ejecutar desde la raíz:

    python stages/01_python_window/app.py

El resultado esperado es que aparezca la ventana y que Cerrar y la X terminen
el programa. Esta prueba es opcional y no se realiza en GitHub Pages.

INTEGRACIÓN POSTERIOR
---------------------
Después de terminar esta lección, trasladar la idea a src/interface.py. El
archivo app.py de la raíz será el punto de entrada de la aplicación integrada.

======================================================================
ARCHIVO: preview.html
======================================================================

PROPÓSITO
---------
Mostrar en GitHub Pages una representación visual de la ventana que se construye
en app.py. Este archivo no ejecuta Python ni Tkinter; solo permite revisar el
resultado visual desde el navegador.

CONCEPTOS NECESARIOS
--------------------
- HTML define la estructura.
- CSS define colores, tamaños y distribución.
- La ruta ../../assets/stage-preview.css reutiliza los estilos del proyecto.

FRAGMENTOS DE REFERENCIA
-------------------------
    <main class="ventana">
      <h1>Agenda SENA</h1>
      <p>Mi agenda local para PC</p>
      <button>Cerrar</button>
    </main>

La vista debe conservar el título, subtítulo y botón del resultado de Python.

VALIDACIÓN VISUAL EN GITHUB PAGES
------------
Abrir stages/01_python_window/preview.html en un navegador y comprobar que la
ventana visual coincide con el diseño definido para app.py.

FLUJO DE LA LECCIÓN
-------------------
1. Agregar o actualizar app.py en GitHub.
2. Actualizar preview.html con los mismos textos, tamaños, botón e iconos.
3. Subir los cambios y abrir preview.html en GitHub Pages.
4. Cuando la vista cumpla la especificación, agregar la tarjeta de la Clase 01
   en index.html y comprobarla desde la colección.

La validación visual hace parte de la lección. Un cambio de diseño previsto en
app.py debe reflejarse también en preview.html. Pages no ejecuta app.py.
